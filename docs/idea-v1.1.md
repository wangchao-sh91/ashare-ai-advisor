# A 股 AI 投研助手 v1.1：后端数据架构探索

## 1. 文档目的

本文记录 v1.1 后端数据架构变更的探索结论，作为后续 OpenSpec change proposal、设计和任务拆分的输入。本文聚焦金融数据、联网搜索、标的识别和证据充分性，不改变 v1 已确定的本地单用户、临时会话、投资安全和结构化回答原则。

本轮探索只形成方案，不代表已经实施。

## 2. 已确认决策

1. 金融结构化数据源由 AKShare 改为免费版 Tushare。
2. Tushare 通过官方 Python 包接入，并且应用只允许调用 A 股未复权日线接口 `daily`。
3. 用户问题先经过一次结构化 LLM API 调用完成重写，同时获得完整的股票名称、Tushare 股票代码、意图、所需数据类别和时效性信息。
4. 宽基指数继续属于支持范围，但仅使用豆包搜索证据，不再承诺结构化指数行情、区间收益、均线或波动率计算。
5. 股票价格和历史走势只信任 Tushare 日线数据。Tushare 调用失败、返回空数据或校验失败时，不回退到豆包搜索，而是直接将价格类别判定为证据不足。
6. 股票财务、估值、股东、质押、近期事件等 Tushare 免费版无法提供的数据，由豆包 Search API 尝试获取。
7. 豆包搜索由 MCP stdio 子进程方案改为直接 HTTPS API 调用。
8. 每一个用户明确请求的数据类别独立判断证据是否充分；某一类别有证据不能自动满足另一个类别。
9. 支持结合 Tushare 日线与豆包搜索取得的新闻、公司公告和监管公告分析单只 A 股走势；该能力只描述价格行为与事件的时序关联，不作因果认定。

## 3. v1.1 能力边界

| 标的或问题 | 数据类别 | 首选来源 | 失败行为 |
|---|---|---|---|
| 单只 A 股 | 日线价格、成交量、历史走势 | Tushare `daily` | 不搜索补位，价格证据不足 |
| 单只 A 股 | 财务、估值、股东、质押等 | 豆包 Search API | 无可信结果则对应类别证据不足 |
| 单只 A 股 | 最新公告、政策、公司事件 | 豆包 Search API | 无法核验时仅回答稳定部分或返回证据不足 |
| 单只 A 股 | 基于日线和新闻公告的走势分析 | Tushare `daily` + 豆包 Search API | 两类证据独立降级；价格失败时不能完成走势分析 |
| 宽基指数 | 行情、事件和背景信息 | 豆包 Search API | 无可信结果则证据不足 |
| 稳定金融知识 | 概念和机制解释 | DeepSeek 模型知识 | 不强制调用外部数据源 |
| 时效性金融知识 | 最新规则、政策和市场事实 | 豆包 Search API | 无法核验时不得输出时效性结论 |

宽基指数回答必须标记为搜索支撑的公开信息。搜索摘要不得伪装成 Tushare 行情记录，也不得被用于构造需要完整时间序列的确定性指标。

## 4. 目标数据链路

```text
当前问题 + 当前页面内的有界上下文
                 │
                 ▼
     一次结构化 LLM 问题重写调用
       ├── rewritten_question
       ├── intent
       ├── instrument/name/ts_code
       ├── requested_categories
       ├── time_sensitive
       └── clarification_required
                 │
                 ▼
       确定性校验与证据计划
                 │
        ┌────────┴─────────┐
        ▼                  ▼
  A股日线价格类别       其他类别 / 宽基指数
        │                  │
        ▼                  ▼
 Tushare Python SDK    豆包 Search HTTPS API
        │                  │
   规范化与校验        来源筛选、去重与引用
        │                  │
        └────────┬─────────┘
                 ▼
        按数据类别聚合证据
                 │
        ├── 充分：进入回答生成
        ├── 部分：只回答已有证据部分并列出限制
        └── 不足：不生成缺乏证据的研究结论
                 │
                 ▼
       DeepSeek 生成 + 事实与引用校验
                 │
                 ▼
             流式返回前端
```

## 5. 一次 LLM 调用的问题重写与标的识别

### 5.1 调用职责

现有意图分类调用升级为“问题规范化器”，一次调用同时完成：

- 根据当前问题和有界页面上下文重写完整、自包含的问题。
- 识别单股、宽基指数、稳定知识、混合问题或超出范围。
- 提取股票名称、六位代码、交易所后缀及规范化 `ts_code`，例如 `600519.SH`。
- 识别用户明确要求的价格、指数、财务、估值、股东、质押和公司事件等数据类别；新闻、公司公告和监管公告统一规划为 `corporate_event`。
- 判断问题是否涉及最新、近期、当前规则或外部事件。
- 提取明确分析区间；用户未指定时应用受控默认区间，使 Tushare 日线和搜索事件覆盖同一时间范围。
- 判断是否存在歧义并生成澄清需求。

建议的结构化输出至少包含：

```json
{
  "rewritten_question": "贵州茅台（600519.SH）最近一年的价格走势和当前估值如何？",
  "intent": "single_stock",
  "instrument": {
    "name": "贵州茅台",
    "ts_code": "600519.SH",
    "instrument_type": "stock"
  },
  "requested_categories": ["price", "valuation"],
  "analysis_period": {
    "start_date": "20250810",
    "end_date": "20260810"
  },
  "time_sensitive": true,
  "clarification_required": false,
  "clarification": null
}
```

### 5.2 防幻觉边界

LLM 输出是受约束的路由结果，不是金融证据，也不能直接选择或调用工具。

- 输出必须通过严格 schema 校验。
- A 股代码必须满足 `六位数字 + .SH/.SZ/.BJ` 格式，并校验代码前缀与交易所的一致性。
- 宽基指数只能落入应用维护的允许列表，不能由模型动态扩展支持范围。
- 当前问题中明确出现的新标的优先于历史上下文。
- 名称、代码或上下文存在冲突时必须要求用户澄清，不能自动猜测。
- 对股票价格路径，Tushare 返回的 `ts_code` 和有效日线记录是代码可用性的下游验证；验证失败即价格证据不足。
- 对仅搜索支撑的类别，搜索词应同时带规范名称和代码。搜索结果不能合理对应两者时，不得形成该标的的证据。
- 模型无法高置信度补全名称或代码时，应保留缺失字段并要求澄清，而不是编造完整标的信息。

该方案取消运行时依赖 AKShare 股票目录，但也意味着标的识别质量成为独立的模型契约，需要通过大量名称、代码、简称、同名、错别字和上下文跟进测试约束。

## 6. Tushare 日线适配方案

### 6.1 接口限制

应用通过固定版本的 `tushare` Python 包创建 Pro 客户端，只允许调用：

```python
pro.daily(ts_code=..., start_date=..., end_date=...)
```

不调用 `stock_basic`、`daily_basic`、指数行情、财务、股东、质押或其他需要额外积分的接口。Tushare 官方日线接口返回未复权 A 股日线，参数和字段以[官方日线文档](https://tushare.pro/document/2?doc_id=27)为准。

### 6.2 网关约束

- Python SDK 是同步接口，应放入受限线程池，不能阻塞 FastAPI 事件循环。
- 设置总超时、最大并发、有限重试和取消传播。
- token 仅从服务端 Secret 配置读取，不写入代码、不传给浏览器、不进入日志。
- 网关只接受允许的 `ts_code`、开始日期、结束日期和字段集合。
- 缓存键由规范化 `ts_code`、日期范围和字段集合组成。
- Tushare 权限错误、限流、超时、空数据和字段变化要映射为稳定、脱敏的内部错误。
- 生产配置使用 HTTPS；不因 SDK 或文档示例而允许明文 token 传输。

### 6.3 数据规范化

Tushare 字段需要映射到现有规范化市场记录：

| Tushare 字段 | 规范字段 | 原始单位 | 建议规范单位 |
|---|---|---|---|
| `trade_date` | `observed_at` | `YYYYMMDD` | 日期 |
| `open/high/low/close/pre_close` | 同名价格字段 | 元 | CNY |
| `change` | `change` | 元 | CNY |
| `pct_chg` | `change_pct` | 百分比 | percent |
| `vol` | `volume` | 手 | shares，乘以 100 |
| `amount` | `turnover` | 千元 | CNY，乘以 1000 |

只有通过日期、数值、单位、重复记录、样本量和字段完整性校验的数据才能进入确定性指标计算。区间收益、均线、成交量变化和历史波动率继续由程序计算，不能由模型或搜索摘要计算。

### 6.4 失败策略

股票价格类别不采用搜索回退：

- Tushare 调用失败：价格证据不足。
- 返回空记录：价格证据不足。
- 代码不匹配或字段异常：价格证据不足。
- 数据过旧：可以保留实际数据，但必须显示真实截止时间和陈旧限制。
- 用户同时请求价格和估值时，价格失败不妨碍系统独立尝试估值搜索；最终只能回答证据充分的类别。

## 7. 豆包 Search API 方案

### 7.1 传输与鉴权

删除 MCP stdio 子进程、工具发现、生命周期监督及 MCP Server 安装。改用官方推荐的 API Key 方式直接调用：

- `POST https://open.feedcoopapi.com/search_api/web_search`
- `Authorization: Bearer <API_KEY>`
- `Content-Type: application/json`

当前官方文档说明默认限流为账号级 5 QPS，每个火山账号每月免费调用 500 次；免费额度耗尽错误为 `10406`，QPS 超限错误为 `700429`。请求与响应契约以[豆包搜索 Custom 版官方文档](https://docs.volcengine.com/docs/87772/2272953?lang=zh)为准。

### 7.2 建议请求策略

```json
{
  "Query": "贵州茅台 600519.SH 最新估值 官方",
  "SearchType": "web",
  "Count": 5,
  "Filter": {
    "NeedUrl": true,
    "AuthInfoLevel": 1
  },
  "QueryControl": {
    "QueryRewrite": false
  },
  "Industry": "finance",
  "TimeRange": "OneMonth"
}
```

具体策略：

- `NeedUrl=true`，没有可访问来源链接的结果不能成为普通网页引用。
- 金融数据搜索设置 `Industry=finance`。
- 公告、监管规则和交易所信息优先使用 `AuthInfoLevel=1`；若严格权威搜索为空，是否进行一次放宽搜索应受配额预算控制。
- 应用已经完成问题重写，因此默认关闭豆包 `QueryRewrite`，避免二次改写偏离标的或数据类别。
- `TimeRange` 根据用户问题映射为 OneDay、OneWeek、OneMonth、OneYear 或明确日期区间。
- 对 `corporate_event` 搜索，query 必须同时包含规范股票名称、`ts_code` 和公告或新闻意图；搜索时间范围与日线分析区间一致。
- 上下文优先采用 `Summary`；`Snippet` 只作为列表摘要和兜底，不将不受限 `Content` 直接放入模型上下文。
- 搜索结果中的文本始终视为不可信外部内容，必须隔离提示词注入式指令。

### 7.3 响应规范化

从 `Result.WebResults` 提取并校验：

- `Id`
- `Title`
- `SiteName`
- `Url`
- `Snippet` 或 `Summary`
- `PublishTime`
- `RankScore`
- `AuthInfoDes` 和 `AuthInfoLevel`
- 应用侧获取时间

应用继续执行 URL 校验、同 URL 去重、权威来源优先、不同可信来源冲突保留及最大证据文本限制。提供方相关性评分不能替代应用自己的来源可信度判断。

### 7.4 配额策略

500 次/月不足以支持无约束的多类别逐次搜索，因此需要：

- 对规范化 query、时间范围、权威过滤和站点过滤建立非会话型 TTL 缓存。
- 同一问题相关类别可合并为一次有边界的搜索，但返回证据仍需分别归类。
- 每个用户请求默认最多一次搜索；只有明确的严格权威搜索降级策略才允许第二次调用。
- `10406` 映射为配额耗尽，不进行无意义重试。
- `700429` 和可恢复的服务端错误采用带抖动的有限退避。
- readiness 只检查必要配置；运行时配额耗尽作为搜索能力降级公开，不泄露账号信息。

## 8. 按类别证据充分性

### 8.1 类别状态

每个请求的数据类别独立产生以下状态：

- `available`：存在通过校验且能支持用户问题的证据。
- `unavailable`：提供方失败、额度耗尽或没有结果。
- `invalid`：数据存在但字段、单位、日期、标的对应关系或来源质量不合格。
- `unsupported`：v1.1 明确不支持的类别或计算。

### 8.2 判定原则

- 股票价格只能由有效 Tushare 日线证据满足。
- 搜索结果只能满足其明确关联的数据类别。
- 财务或估值数字必须能识别指标名称、数值、单位、报告日期和来源；只有泛泛描述时不能作为结构化数值事实。
- 搜索证据可以作为 `WEB_FACT`，不能冒充 `MARKET_FACT`。
- 宽基指数搜索结果不能用于生成依赖完整序列的区间收益、均线或波动率。
- 用户明确请求的核心类别没有证据时，对该部分返回证据不足，不让模型补齐。
- 一个类别失败时，可以保留其他类别的有效证据并形成部分回答，但必须列出受影响类别和限制。
- 所有类别均无证据时终止研究回答，只返回可操作的证据不足说明。

### 8.3 日线与新闻公告联合分析

当用户要求“结合日线和新闻公告分析某只股票走势”时，问题规范化器必须至少规划两个独立类别：

- `price`：由 Tushare `daily` 提供日线和成交量序列。
- `corporate_event`：由豆包 Search API 提供新闻、公司公告、交易所公告或监管公告。

```text
重写后的问题 + 统一分析区间
              │
       ┌──────┴──────┐
       ▼             ▼
 Tushare 日线     新闻与公告搜索
       │             │
 收益/量价/波动   来源/发布时间/事件摘要
       │             │
       └──────┬──────┘
              ▼
     映射到有效交易日时间轴
              │
              ▼
     事件窗口与价格行为对照
              │
              ▼
  事实、时序关联、其他可能因素和限制
```

#### 事件证据要求

- 公司官网、交易所、巨潮资讯、监管机构等正式公告优先作为一手来源。
- 主流媒体报道作为二手来源，不能覆盖或替代相冲突的一手公告。
- 每个事件至少包含标题、目标股票、来源 URL、发布时间或发布日期、支持的事实及应用获取时间。
- 搜索结果无法同时对应规范股票名称和代码时，不得归入该股票的 `corporate_event` 证据。
- 同一事件的转载应去重；不同可信来源存在实质冲突时必须同时保留并显示不确定性。
- 没有可靠发布时间的事件可以展示，但不能用于事件窗口计算。

#### 事件与交易日对齐

- 交易时段内发布且时间可靠的事件映射到当日交易日。
- 收盘后发布的事件映射到下一有效交易日。
- 周末、节假日或其他非交易日发布的事件映射到下一有效交易日。
- 只有发布日期、没有具体时刻时，默认映射到下一有效交易日，并标记时间精度限制。
- 事件窗口只能使用 Tushare 实际返回的有效交易日，不能用自然日填补停牌或休市缺口。

可由程序确定性计算的观察项包括事件前后 1、3、5 个交易日收益、成交量变化、价格区间和波动率变化。由于 v1.1 不再取得结构化宽基指数日线，不能计算基准调整后的异常收益，也不能将该功能称为严格的事件研究。

#### 分析表达边界

联合回答必须分开呈现：

1. Tushare 日线直接支持的价格和成交量事实。
2. 新闻公告直接支持的事件事实及引用。
3. 程序计算的事件窗口指标。
4. 模型对时序关系的解释、其他可能影响因素和限制。

允许表述“事件发布后的三个交易日股价下跌，成交量放大，时间上与该事件接近”。禁止表述“该事件导致股价下跌”，除非存在额外、可验证且足以支持因果判断的证据；v1.1 默认不提供这种因果认定。

#### 组合失败行为

| 日线证据 | 新闻公告证据 | 结果 |
|---|---|---|
| 可用 | 可用 | 生成完整的量价事实、事件事实和时序关联分析 |
| 可用 | 不可用或无可信结果 | 仅回答量价走势，明确未能核验相关事件 |
| 不可用或无效 | 可用 | 可以总结事件，但不能完成用户要求的走势分析 |
| 不可用或无效 | 不可用或无可信结果 | 整体证据不足，不生成研究结论 |

对于明确要求“基于日线和新闻公告分析走势”的问题，`price` 是完成走势分析的必需类别，且不能通过搜索补位；`corporate_event` 失败时只能形成明确降级的量价回答，不能假装已经完成事件关联分析。

## 9. 对现有后端的预期影响

| 当前区域 | v1.1 方向 |
|---|---|
| `akshare_gateway.py` / `akshare_allowlist.py` | 删除并替换为单操作 `TushareGateway` |
| `market_normalizer.py` | 保留日线规范化核心，改为 Tushare 英文字段和正确单位；移除不再支持的 AKShare normalizer |
| `live_market.py` | 仅执行股票日线证据路径 |
| `routing.py` | 升级为一次结构化问题重写、分类和标的提取调用 |
| `entity_resolution.py` / `instrument_resolver.py` | 移除启动时 AKShare 股票目录依赖，改为校验 LLM 的结构化标的结果和上下文冲突 |
| `planning.py` | 为每个类别明确 provider 路由、required 状态和失败策略 |
| `execution.py` | 改为按类别执行、回填和判定充分性，禁止任意 web evidence 满足无关类别 |
| `doubao_mcp.py` | 删除 |
| `search_gateway.py` | 保留领域请求/响应模型，底层改为异步 HTTPS API client |
| `main.py` / `runtime.py` | 删除 MCP lifespan；创建共享的 Tushare 和豆包 API client |
| `health.py` | readiness 从 MCP 进程状态改为 token/API Key 配置与 orchestrator 状态 |
| `domain/models.py` | `SourceType.AKSHARE` 改为 `TUSHARE`，完善类别来源和搜索错误分类 |
| `pyproject.toml` | 移除 AKShare 和 MCP Server 依赖，加入并固定 Tushare 包；保留实际需要的 HTTP 客户端 |
| Docker / Compose | 删除 MCP 可执行文件安装与子进程管理，新增 Tushare token 和豆包 API Key 配置 |

## 10. 配置与安全

建议生产配置统一使用环境变量或 Pydantic Secret：

- `TUSHARE_TOKEN`
- `TUSHARE_TIMEOUT_SECONDS`
- `TUSHARE_MAX_RETRIES`
- `TUSHARE_MAX_WORKERS`
- `DOUBAO_SEARCH_API_KEY`
- `DOUBAO_SEARCH_TIMEOUT_SECONDS`
- `DOUBAO_SEARCH_MAX_RETRIES`
- `MARKET_DATA_CACHE_TTL_SECONDS`
- `SEARCH_CACHE_TTL_SECONDS`

本地 `.tushare` 文件只用于人工调试脚本，不作为容器生产配置契约。日志不得记录 token、API Key、Authorization header、完整对话、完整网页正文或未清洗的提供方响应。

## 11. 测试与验证重点

### 11.1 问题重写

- 股票全名、简称、代码、交易所前后缀和中英文混合输入。
- 名称与代码冲突、同名歧义、无效代码和模型缺失字段。
- “它的估值呢”等当前页面上下文跟进。
- 后续问题显式切换标的时覆盖旧上下文。
- 一次模型调用同时输出意图、标的和类别，不产生模型选择的工具名。
- “结合日线和公告分析走势”必须输出 `price`、`corporate_event` 和统一 `analysis_period`。

### 11.2 Tushare

- 成功、空数据、无权限、无效 token、限流、超时和字段变化。
- `vol` 从手转换为股，`amount` 从千元转换为元。
- 日期倒序、重复日期、停牌缺口和样本不足。
- Tushare 失败后断言没有发起价格搜索回退。

### 11.3 豆包 Search API

- Bearer 鉴权、请求字段、超时、取消和有限重试。
- `Result.WebResults` 正常、为空、缺 URL、缺发布日期和结构异常。
- `10406` 配额耗尽、`700429` QPS 超限和服务端错误。
- 权威来源优先、重复 URL、可信来源冲突和提示词注入式正文。
- 宽基指数只产生 Web Evidence，不产生伪造的结构化行情记录。
- 公司公告、交易所公告、监管公告和媒体新闻能正确区分来源质量并映射到目标股票。

### 11.4 端到端路由

- 单股价格：只调用 Tushare。
- 单股估值：只调用搜索。
- 单股价格加估值：两个类别独立执行和判定。
- 单股日线加新闻公告：两侧成功时形成时间轴和事件窗口观察。
- 日线成功、新闻公告失败：只形成量价部分回答。
- 日线失败、新闻公告成功：可以总结事件，但不能形成走势分析。
- 收盘后、周末及只有发布日期的公告正确映射到下一有效交易日。
- 联合分析不得把时序接近表述为事件导致价格变化。
- 宽基指数：只调用搜索。
- Tushare 价格失败但搜索可用：价格仍然证据不足。
- 搜索失败但 Tushare 价格可用：允许形成仅包含价格证据的部分回答。
- 两侧都没有有效证据：返回证据不足，不调用模型生成研究结论。

## 12. OpenSpec 变更范围建议

建议创建 change：

```text
replace-market-providers-with-tushare-and-doubao-api
```

预计修改以下主 specs：

- `market-data-grounding`：替换数据源、限制为 A 股日线、定义单位转换、无价格回退及事件窗口确定性计算规则。
- `web-search-grounding`：MCP 改为 HTTPS API，增加金融类别搜索、新闻公告证据、鉴权、额度、限流和错误行为。
- `research-question-answering`：定义一次 LLM 问题重写、宽基指数仅搜索、按类别证据充分性、部分回答及日线与事件联合分析规则。

`ephemeral-chat-workspace` 原则上不需要行为变更，但前端可能需要展示更明确的类别级证据不足、配额耗尽和部分回答提示。

## 13. 实施前仍需通过 spike 固化的参数

以下项目不阻塞 proposal，但应在设计或任务中安排短期兼容性验证：

- 固定的 `tushare` Python 包版本及其异常类型、超时和线程取消行为。
- Tushare SDK 是否始终使用 HTTPS，以及应用如何强制或验证安全端点。
- DeepSeek V4 Pro 的准确模型标识及结构化输出稳定性。
- 豆包 Search API 的真实返回 fixture、错误 envelope 和响应 header。
- 市场数据与搜索缓存的 TTL、最大容量和是否需要跨进程共享。
- 严格权威搜索为空时是否允许一次放宽 `AuthInfoLevel` 的配额预算。

## 14. 探索结论

v1.1 的核心不是“AKShare 换成 Tushare、MCP 换成 HTTP”，而是建立明确的数据权威边界：股票日线和确定性价格计算只来自 Tushare；其余可公开核验的信息来自豆包搜索；每个数据类别独立判定证据；任何来源失败都不能由模型补全。日线与新闻公告可以在统一交易日时间轴上联合解释，但只能形成可核验的时序关联，不能把相关性包装成因果关系。

通过把当前分类调用升级为一次结构化问题重写调用，可以在不增加额外 LLM 往返的前提下获得完整股票名称和代码，并移除对 AKShare 股票目录的运行时依赖。相应风险通过严格 schema、代码语法校验、歧义澄清、Tushare 下游验证以及搜索结果的名称代码一致性检查控制。

以上决策已经足够进入 OpenSpec proposal 阶段。
