# A 股 AI 投研助手：第一版产品构想

## 1. 产品定位

本项目是一款面向本地单用户的 A 股 AI 投研助手。第一版聚焦“投研问答”，帮助用户基于公开市场数据和公开网络信息，快速理解单只 A 股、宽基指数及基础金融知识。

产品提供的是研究辅助与信息整理能力，不提供确定性的收益承诺、个性化投资建议或自动交易能力。所有输出均应明确区分客观事实、模型分析和风险提示，并标注数据或信息来源及截止时间。

## 2. 第一版目标

第一版需要验证以下核心价值：

- 用户能用自然语言询问单只 A 股或宽基指数相关问题。
- 系统能获取、计算和解释公开行情及基本面数据。
- 系统能回答不依赖实时行情的基础金融知识问题。
- 当问题涉及时效性知识或外部事件时，Agent 能通过豆包搜索 Tool 联网检索。
- 回答结构清晰、数字可追溯，并对数据缺失、时效性和投资风险作出明确提示。

## 3. 目标用户与部署形态

- 面向具备基本投资认知、希望提高信息获取和研究效率的个人用户。
- 采用本地部署、单用户使用模式。
- 第一版不提供注册、登录、权限、订阅及多用户隔离功能。
- 应用服务与必要缓存均运行在本地；大模型推理通过云端 DeepSeek V4 Pro API 完成。

## 4. 功能范围

### 4.1 投研标的范围

第一版仅支持：

- 单只 A 股，包括沪市、深市和北交所股票；实际覆盖范围以 AKShare 可稳定取得的数据为准。
- 宽基指数，例如上证指数、深证成指、创业板指、科创 50、沪深 300、中证 500 和中证 1000 等。

第一版不支持行业、主题概念、多股对比、基金、债券、期货、港股、美股及投资组合分析。用户问题超出范围时，系统应解释当前能力边界，而不是拼凑结论。

### 4.2 投研数据问答

可支持的典型问题包括：

- 近期走势、区间涨跌幅及相对宽基指数表现。
- 成交量、换手率、振幅、均线和历史波动率等量价指标。
- 财务表现、盈利能力、资产负债及主营业务构成概览。
- 当前估值及历史区间位置；仅在数据完整且口径一致时提供估值分位数。
- 股东户数、北向持股、股权质押等公开数据；具体能力取决于接口可用性。
- 基于已取得事实的风险归纳和观察要点。

不提供精确股价预测、保证性结论、明确买卖点或直接的买入/卖出建议。

### 4.3 基础金融知识问答

用户可以询问不限定具体标的的金融知识，例如：

- 市盈率、市净率、ROE、自由现金流等指标的定义和使用方式。
- 除权除息、分红、回购、增发等市场机制。
- 宽基指数、指数编制、技术指标和常见风险概念。
- 财务报表之间的关系及常见分析方法。

此类问题不强制调用 AKShare。Agent 应根据问题选择：

1. 对稳定、基础且无需最新信息的知识，直接由模型解释。
2. 对涉及最新规则、近期事件、当前市场信息或需要事实核验的问题，调用豆包搜索 Tool。
3. 对同时包含知识解释和具体标的数据问题，组合使用知识解释、AKShare 数据和必要的联网搜索。

## 5. 核心交互

第一版沿用现有 Penpot UX 中的投研问答工作区，核心元素包括：

- 问题输入框和发送操作。
- 当前对话中的用户消息与 AI 回答。
- 新建对话和清空对话。
- 分析状态和错误状态。
- 数据来源、信息来源和截止时间。
- 投资风险免责声明。

第一版应隐藏或禁用首页、自选股、市场行情、研报中心、投资组合和设置等未实现入口。附件功能也不纳入第一版，避免用户误以为系统支持上传财报、公告或研报。

### 5.1 对话生命周期

- 对话上下文只存在于当前页面会话中。
- 不将消息或上下文写入数据库或其他持久化存储。
- 刷新页面、关闭浏览器或重新打开应用后，显示无历史对话的初始界面。
- “新建对话”和“清空对话”在第一版中的含义相同：清除当前上下文并回到初始状态。
- 清除上下文不应删除行情数据缓存等非会话型技术缓存。

## 6. 回答组织方式

具体标的的投研回答优先采用以下结构：

1. **结论摘要**：简要说明观察结果，不使用确定性预测语言。
2. **事实**：列出由行情、财务或公开资料直接支持的数值与事件。
3. **分析**：解释事实之间的关系，并明确这是研究判断而非客观事实。
4. **风险提示**：列出数据质量、市场、公司、政策等相关风险。
5. **来源与时效**：展示 AKShare 接口对应的上游来源、网络搜索来源、数据区间、截止日期和获取时间。
6. **免责声明**：说明内容仅供研究参考，不构成投资建议。

纯金融知识回答不必机械套用“事实 / 分析 / 风险提示”，但应保持结构清楚；使用联网搜索时必须给出可核验的来源。

## 7. Agent 决策与数据链路

```text
用户问题
   │
   ▼
意图与实体识别
   │
   ├── 单股/宽基指数投研问题
   │      │
   │      ├── 制定数据计划
   │      ├── 调用 AKShare
   │      ├── 标准化并校验数据
   │      ├── 由程序计算指标和事实
   │      └── 必要时调用豆包搜索补充时效信息
   │
   ├── 基础金融知识问题
   │      │
   │      ├── 稳定知识：模型直接解释
   │      └── 时效性/需核验：调用豆包搜索
   │
   └── 超出范围的问题
          └── 说明能力边界并建议可支持的问法
   │
   ▼
组织证据与来源
   │
   ▼
DeepSeek V4 Pro 生成回答
   │
   ▼
事实一致性与引用检查
   │
   ▼
流式返回前端
```

模型不应直接根据零散接口结果自行计算关键数字。区间收益、相对收益、均线、波动率、同比变化和估值分位等指标应由确定性程序计算，再作为结构化事实提供给模型解释。

## 8. 外部能力

### 8.1 AKShare

AKShare 是第一版的主要金融数据访问层，用于获取 A 股、宽基指数、行情、财务及其他公开数据。

使用时需要注意：

- AKShare 是数据聚合接口，不应被表述为所有数据的原始发布方。
- 应同时记录 AKShare 接口名称及其标明的上游数据源。
- 不同接口的更新时间、历史范围、字段口径和稳定性可能不同。
- 上游站点变化可能造成接口暂时不可用或字段变化。
- 数据缺失、过期或校验失败时，应降级回答或明确告知用户，不能让模型补全数字。

### 8.2 豆包搜索 Tool

豆包搜索用于获取或核验互联网公开信息，主要服务于：

- 最新市场规则和政策。
- 近期公司事件或宏观事件。
- 具有时效性的金融知识。
- AKShare 无法覆盖的公开背景信息。

搜索结果属于外部证据而非模型自身知识。系统应保留结果标题、链接、发布时间、获取时间和摘要，优先采用权威的一手来源，并在回答中展示引用。

### 8.3 DeepSeek V4 Pro API

DeepSeek V4 Pro 用于问题理解、工具选择、证据综合和自然语言回答。接入层应隔离具体模型协议，使后续替换模型或调整版本时不影响业务层。

模型输入中不应包含本地密钥或无关敏感信息。API 密钥仅保存在本地服务端配置中，不暴露给浏览器。

## 9. 建议的逻辑模块

```text
前端问答界面
      │
      ▼
本地 API / 流式响应层
      │
      ▼
Agent 编排层
  ├── 意图与标的识别
  ├── 工具选择
  ├── 上下文管理（仅内存）
  ├── 证据整合
  └── 回答校验
      │
      ├── AKShare 数据适配层
      │     ├── 数据获取
      │     ├── 字段标准化
      │     ├── 指标计算
      │     └── 非会话型缓存
      │
      ├── 豆包搜索 Tool
      │
      └── DeepSeek V4 Pro API
```

## 10. 数据与引用要求

每次投研回答应尽可能保存或在当前请求中维护以下元数据：

- 标的名称、代码和交易所。
- 问题分类及分析区间。
- 作为比较基准的宽基指数。
- 实际采用的交易日范围。
- AKShare 接口名称和上游数据源。
- 搜索结果链接、发布日期和获取时间。
- 数据截止时间及接口调用时间。
- 缺失值、接口异常和数据完整性检查结果。
- 由程序计算的指标及其计算口径。

页面刷新后无需保存这些会话级元数据，但应用日志中可以保留必要的技术错误信息；日志不应被设计成变相的会话历史。

## 11. 异常与降级策略

- 无法识别股票名称或代码时，引导用户补充标的信息。
- 同名或歧义标的不能自动猜测，应列出候选项。
- AKShare 接口不可用时，说明失败的数据项；若证据不足，不生成对应分析。
- 搜索不可用时，可以回答稳定知识，但必须说明无法核验最新信息。
- DeepSeek API 超时或限流时，展示可重试错误，不丢失当前输入。
- 数据日期早于用户预期时，明确展示实际截止日期。
- 用户请求买卖建议或收益保证时，转为提供研究框架、客观数据和风险说明。

## 12. 第一版非目标

- 用户注册、登录、权限和多租户。
- 对话历史和跨会话记忆。
- 自选股、投资组合及收益跟踪。
- 行情看板和专业交易终端能力。
- 券商研报库和公告全文知识库。
- 文件或图片上传分析。
- 行业、概念板块和多标的横向比较。
- 策略回测、模拟交易和实盘交易。
- 个性化推荐、投资适当性判断或自动投资决策。

## 13. MVP 成功标准

- 用户能通过股票名称或代码询问受支持标的，并获得结构化回答。
- 回答中的关键数值来自程序计算的结构化数据，而非模型臆测。
- 每个时效性结论都有数据日期或网络来源。
- 数据不可用时系统能明确降级，不伪造或补齐事实。
- 基础金融知识问题无需依赖 AKShare 也能获得清晰回答。
- 需要最新信息时，Agent 能正确选择豆包搜索并展示引用。
- 新建、清空、刷新和重新打开应用后均符合无持久化会话的预期。
- 未实现的导航和附件入口不会让用户误判产品能力。

## 14. 后续待明确事项

- 第一版首批正式支持的股票与宽基指数清单，以及名称、代码、交易所的映射规则。
- 各类问题对应的 AKShare 接口白名单、数据口径和降级优先级。
- 豆包搜索 Tool 的请求协议、引用字段、配额和失败行为。
- DeepSeek V4 Pro API 的准确模型标识、上下文窗口、流式协议、费用及限流策略。
- 是否允许把非会话型行情数据缓存在本地磁盘，以及缓存有效期。
- 对回答中“来源”的展示粒度：接口级、原始页面级或具体数据项级。
- 本地运行所需的操作系统、容器化方式及最低硬件要求。
